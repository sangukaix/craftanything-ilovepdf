# 계정·보관함·결제 테스트 모드

현재 구현은 iLovePDF 공식 서비스와 별개의 자체 계정 시스템입니다. 외부 클라우드 계정·배포 주소·결제사 키가 없어 **로컬 계정과 모의 결제를 검증**합니다. 실제 카드 청구, 자동 구독, 외부 이메일 전송은 없습니다.

## 로컬 사용

1. `start-local-pdf.cmd` 실행. 미리보기 8766, 문서 API 8767, 계정 API 8768을 loopback으로 시작합니다.
2. `/ko/register/`에서 테스트 계정을 만듭니다. 비밀번호는 10~128자입니다.
3. `/ko/account/`에서 PDF 업로드·다운로드·삭제와 주문 내역을 확인합니다.
4. `/ko/pricing/` → 모의 결제 시작 → 성공/실패/취소를 시험합니다.

기본 한도: PDF 5개, 합계 25MB. 모의 이용권: 1,000원이라는 **시험 금액**, 30일 동안 50개/합계 200MB. 파일당 25MB. PDF 기능 자체에는 결제를 요구하지 않습니다. 실제 서비스 가격과 관계없습니다.

비밀번호는 사용자별 salt와 scrypt로 해시합니다. 로그인 쿠키는 HttpOnly/SameSite=Strict이며 요청 인증 토큰을 확인합니다. 계정 DB와 AES-GCM 암호화 보관 파일은 `.local-data/accounts/accounts.sqlite3`, 암호화 키는 같은 폴더의 `vault.key`에 저장합니다. 사용자별 조회·삭제 권한을 확인하며 파일명으로 저장 경로를 만들지 않습니다. 이 폴더 전체는 Git에서 제외합니다. 키를 잃으면 보관 파일을 복구할 수 없습니다. 소스/테스트 보고서 ZIP에 넣지 마세요. 실행 중 DB 백업은 SQLite 백업 API를 사용해야 합니다.

## Toss 테스트 연동 코드

서버를 시작하는 PowerShell 세션의 환경 변수만 사용합니다. 코드가 `.env`나 기존 키 파일을 읽지 않습니다.

- `PDF_TOSS_TEST_CLIENT_KEY`: 본인 결제사 개발자센터의 **test_** 클라이언트 키
- `PDF_TOSS_TEST_SECRET_KEY`: 대응하는 **test_** 시크릿 키 (서버 전용)

둘 다 있어야 UI에 Toss 테스트 버튼이 나타납니다. `live_` 키는 거절합니다. 키를 넣은 세션에서 계정 서비스만 다시 시작해야 적용됩니다. 로그·채팅·소스에 시크릿 키를 넣지 마세요.

V2 위젯 SDK → 서버 저장 주문 금액 → 테스트 승인 API 순서입니다. 성공 리다이렉트의 금액만 신뢰하지 않습니다. 주문 소유권·금액·통화·DONE 상태·paymentKey를 대조하고, 주문 UUID에서 만든 고정 UUID v4 Idempotency-Key를 사용합니다. DB 트랜잭션으로 이용권은 한 번만 적용됩니다. 웹훅도 요청 내용으로 즉시 승인하지 않고 결제사 API로 다시 조회합니다.

키가 없는 현재 검증: 모의 결제 HTTP 통합, 결제사 응답을 대체한 계약 테스트, 중복/변조/소유권 테스트. **Toss 실제 테스트 서버 왕복, 위젯 화면, 외부 웹훅 수신은 미검증**입니다. 결제 취소/환불 API와 정기 구독은 이번 모의 이용권에 포함되지 않습니다. 클라이언트의 취소/실패 리다이렉트만으로 서버 주문을 확정하지 않습니다.

공식 문서: https://docs.tosspayments.com/guides/v2/get-started/llms-quick-reference

## 외부 배포를 준비할 때

선택한 호스팅의 HTTPS 도메인과 영구 디스크가 필요합니다. 계정 API는 계속 127.0.0.1:8768에 두고, HTTPS 프록시의 `/account-api/*`를 이 서비스의 `/*`로 전달합니다. 내부 Host는 `127.0.0.1:8768`로 설정합니다.

- 서버 환경: `PDF_WEB_ORIGIN=https://선택한도메인` (끝 슬래시 없이)
- Next 빌드 환경: `NEXT_PUBLIC_ACCOUNT_API=/account-api`
- HTTPS 출처에서는 Secure 쿠키를 추가합니다. 프록시의 요청 크기 한도는 35MB 이상이 필요합니다.
- `.local-data`는 웹 정적 폴더 밖의 영구 디스크에 보관하고 계정 서비스 한 인스턴스만 사용합니다. 현재 SQLite 설계는 다중 서버 동시 운영용이 아닙니다.
- 결제사 success/fail URL과 외부 웹훅 `/account-api/api/webhook/toss`를 해당 HTTPS 주소로 등록합니다.

현재 전체 PDF 처리 서비스는 로컬 PC용이며, 클라우드 PDF 처리 엔드포인트·작업 격리·대기열·스토리지 제공자 어댑터를 배포하지 않았습니다. 자체 계정의 이메일 검증/복구, Google·Microsoft 로그인, S3·Drive 동기화, 상용 운영 모니터링도 아직 연결되지 않았습니다. 배포 템플릿만으로 상용 서비스가 완성됐다고 보지 마세요. 외부 제공자를 정한 다음 그 서비스의 테스트 키와 별도 테스트 계정으로 끝까지 검증해야 합니다.
